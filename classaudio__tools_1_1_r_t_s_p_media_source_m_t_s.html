Detailed Description

IMediaSource for an MPEG transport stream, e.g. live video and audio muxed by MuxerMTS: the muxer writes its output to this object (it is a Print), and an RTSPMediaStreamer sends it as one RTP track (MP2T, RFC 2250 - see RTSPFormatMTS) to the RTSP client, which demuxes video and audio itself.

Unlike RTSPOutput's generic byte stream, this source is meant for a live stream written from other tasks (e.g. by VideoMuxerWithTasks):

  • the data is kept as complete 188 byte TS packets in a fixed size, lock-free single producer/single consumer ring buffer (RingBufferSPSC), and every RTP packet contains whole TS packets (up to 7: 1316 bytes, below the usual MTU);
  • it is a packetized source (packetSize()), so the streamer sends all queued packets at each timer tick instead of a fixed amount: the send rate adapts to the bitrate of the stream;
  • while no client is streaming, the data is dropped, so a new client doesn't get old data;
  • if the network is slower than the stream, video is dropped rather than audio: when the buffer is filled to 3/4, the video packets are dropped from the start of the next video frame on, until the buffer is half empty again and the next keyframe starts (MuxerMTS writes the PAT before each keyframe). So the picture freezes for a moment while the sound continues. Audio and the other packets are only dropped if the buffer is completely full. Audio and video are recognized by the stream id of their PES packets, so this works with any transport stream. See droppedPackets() and droppedVideoPackets(). A client starts decoding at the next keyframe: MuxerMTS repeats the stream description (PAT/PMT) before each one.

The data can be written from any task, but not from several tasks at the same time - e.g. by a MuxerMTS driven by VideoMuxerWithTasks, which serializes the writes of its audio and video task with its mutex.
