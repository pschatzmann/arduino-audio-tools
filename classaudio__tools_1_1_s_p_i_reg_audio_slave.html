Detailed Description

SPI audio slave based on the TinySPISlave library: the master controls us via a small register map (see SPIRegAudioRegisters.h):

  • SPIREG_AUDIO_INFO: sample rate, channels and bits per sample
  • SPIREG_MIME: mime type of the audio data
  • SPIREG_AVAILABLE: free space in our buffer (the master uses it for flow control)
  • SPIREG_DATA: the audio data

The received audio is stored in the provided buffer; read it with readBytes() or copy it to an output with StreamCopy. Call update() from loop(): it applies format changes (AudioInfo notifications) in the application context. The SPI frames themselves are processed in the interrupt (RP2040/STM32) or in the TinySPISlave task (ESP32), so the buffer should be safe for one writer (SPI) and one reader (loop), e.g. a RingBuffer.

Note
Requires the TinySPISlave library (ESP32, RP2040/RP2350, STM32).
RingBuffer<uint8_t> buffer(8 * 1024);
SPIRegAudioSlave slave(buffer);
auto cfg = SPIRegAudioSlaveConfig();
cfg.sck = 18; cfg.miso = 19; cfg.mosi = 23; cfg.cs = 5;
slave.begin(cfg);
slave.addNotifyAudioChange(i2s); // format is set by the master
StreamCopy copier(i2s, slave);
void loop() { slave.update(); copier.copy(); }
